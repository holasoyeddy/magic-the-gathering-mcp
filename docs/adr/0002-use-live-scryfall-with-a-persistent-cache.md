# Use live Scryfall with a persistent cache

The first release will use a shared rate-limited Scryfall client and persist responses locally for at least 24 hours, rather than periodically importing Scryfall bulk data. Live access keeps the local server operationally small and current enough for card facts, while caching follows Scryfall's guidance and reduces pressure on its rate-limited API; bulk import remains an option if later workloads require a full local dataset or high-volume analysis. When live access fails or is rate-limited, an older cached response may be returned only when it is clearly identified as stale. Stale entries remain eligible for 30 days, and least-recently-used eviction keeps the cache at or below 256 MiB. The shared client centrally enforces upstream rate limits, honors `Retry-After`, and makes at most two bounded retries before using stale data or returning an upstream-unavailable error.
